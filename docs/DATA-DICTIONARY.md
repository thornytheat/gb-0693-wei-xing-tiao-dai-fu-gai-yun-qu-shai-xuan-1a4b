# 数据定义

目标经度区间支持跨180度拆分；覆盖只算并集，云掩膜从有效条带扣除，重复条带不增加面积。

输入字段：scene, alias, west, east, cloud_w, cloud_e, quality, price, captured, version。所有ID按字符串保留；空字符串、NULL、N/A、未知与“-”视为缺失，不能当作数值零。数值使用Decimal，输出为十进制字符串。重复业务键相同内容计重复，内容冲突隔离或按明确修订号裁决，不按文件顺序盲目覆盖。

每条证据有原始行号，隔离记录有原因码及原值。时间区间使用半开边界；日期定义在各模块规则内显式声明。输入表头可调序，不得缺列或重复；中文旧编码可上传。规则版本存入运行清单，重跑使用原始文件内容摘要与规则版本共同确定幂等键。复核使用revision乐观锁，陈旧提交返回409。

固定纬带目标为[170,180)与[-180,-170)，只衡量经度覆盖宽度，不宣称球面面积。经度相同端点拒绝，避免无法区分全世界与空条带。采购使用预算1000 CNY的确定性边际覆盖/价格贪心，并非全局最优证明；同分按场景编号排序。完整交付仍以区间并集核验。

## 云区复查记录

复查输入字段：scene, cloud_w, cloud_e。scene须命中父批次M2裁决后的有效场景（canonical），未知场景隔离为`RECHECK_UNKNOWN`，不进入派生。cloud_w/cloud_e遵循主管线坐标契约，支持跨180拆分与全角数字；两端同时留空表示清除该场景原有遮罩，仅一端留空隔离为`CLOUD`。同一场景在同一复查批次中出现不同云区取值，整组隔离为`RECHECK_CONFLICT`（同版异值隔离），取值一致的重复行视为同一条复查。

修正版本沿版本链`run_versions(run_id, revision)`不可变保存：r1为原始批次，复核动作与云区复查均使版本号加1，历史版本payload不被改写。复查请求`recheck_requests`以请求键（批次与复查内容的哈希）幂等，状态为running/succeeded/failed；重试不新增版本，中断可续跑。当前批次指针存于runs.revision，晚到旧修订（基版或目标版落后于链头）返回409 `STALE_REVISION`。

修正版本manifest.recheck记录：parent_run_id/parent_revision（父批次）、applied_scenes（采信场景）、unknown_scenes、rejected（复查隔离）、mask_rows（每场景原云区段数/复查云区段数/新旧有效宽度及差额）、diff（新旧覆盖宽度与区间段、缺口宽度、采购额与采购场景进退）。证据CSV按revision导出，修正版本追加遮罩对照、复查隔离、新旧差额三个区块。
